Ledgerbot is an assistant layer that sits **next to** a B2B pre-accounting application such as
Easytrade. Company users talk to it over WhatsApp, Telegram or e-mail — text, receipt photos,
PDFs, e-invoice XML, voice notes — and Ledgerbot works out what they want, checks their
permissions, computes every number in code, and then answers, asks for approval, or records the
result in the accounting system.

Ledgerbot never reads the Easytrade database and needs no change to the Easytrade codebase to
start. The two systems meet at a small set of **contracts**, and the Easytrade team decides how
deep the integration goes.

```text
 Company users ── WhatsApp · Telegram · e-mail ──▶ Ledgerbot ──▶ answers, drafts, approvals
                                                       │  ▲
             settings · permission matrix · data ◀─────┘  │
                         (read path)                      │
                                                          │ signed webhooks (write path)
                                                          ▼
                                                      Easytrade
```

## Principles

1. **The model understands, code computes.** The language model only returns an intent and raw
   argument strings. Amounts, VAT, FX, totals and balances are computed in Go from integer kuruş,
   and capability output is sent to the user verbatim.
2. **Rules before models.** Common phrasings are matched by deterministic rules in microseconds;
   the LLM is a fallback. Structured e-invoices never touch a model.
3. **Contracts, not coupling.** Ledgerbot consumes four contracts (settings, permission matrix,
   data provider, events) and exposes one REST API.
4. **Fail safe.** If settings cannot be fetched, the last snapshot is served in degraded mode and
   nothing is written. Roles can only make the save mode stricter.
5. **Performance first.** Stateless API replicas, redundant workers, per-company fairness, cached
   tenant snapshots and batched audit writes. See [Deployment](/docs/operations/deployment).
